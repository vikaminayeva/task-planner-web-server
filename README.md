Веб-сервер планировщика задач (REST API & DB Storage).

Описание проекта и его функционал:
*Управление задачами: Добавление, просмотр списка, редактирование, получение по ID и удаление задач.
*Умный календарь повторений: Поддержка правил повторения задач:
*Безопасность: Аутентификация пользователей по паролю с генерацией защищенных JWT-токенов.
*База данных: Хранение данных в легковесной базе SQLite с автоматической инициализацией схемы таблиц и индексов по датам при первом старте.
*Аутентификация и безопасность: Написана Middleware-функция для защиты API-запросов и генерация JWT-токенов при сверке пароля с переменной окружения.
*Контейнеризация приложения: Написан оптимизированный `Dockerfile`. Проект поддерживает многоэтапную сборку (Multi-stage build) для минимизации размера итогового образа.

Технологический стек проекта
* Язык разработки:Go (Golang) 
* Архитектура: REST API (JSON)
* База данных: SQLite

  
1. Сборка Docker-образа
Находясь в корне проекта (где лежит Dockerfile), выполните команду:  docker build -t planner-app .

Запуск контейнера с монтированием SQLite базы выполните команду: 
*Для Git Bash / Linux / macOS:*
docker run -d -p 7540:7540 -e TODO_PASSWORD="12345" -v "\$(pwd)/scheduler.db:/app/scheduler.db" --name planner-container planner-app

*Для Windows Command Prompt (cmd):*
docker run -d -p 7540:7540 -e TODO_PASSWORD="12345" -v "%cd%/scheduler.db:/app/scheduler.db" --name planner-container planner-app


Это мой финальный дипломный проект на курсе. Я написала полноценный бэкенд-сервис (веб-сервер) на языке Golang, который управляет списками задач. 
Проект помог мне изнутри разобраться, как работают веб-серверы, как проектируются базы данных «на стороне разработки» и как устроен сбор сырых данных, с которыми аналитики потом работают.
