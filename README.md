##  Go Task Scheduler (Планировщик задач) 

Высокоуровневый REST API веб-сервер на языке **Go**, реализующий функционал продвинутого планировщика задач (TODO-лист). Проект включает в себя умный движок расчёта периодических дат, постоянное хранение данных в СУБД SQLite, защищенный слой аутентификации на базе JWT, а также готовую инфраструктуру для контейнеризации.

Проект полностью интегрирован с готовым фронтенд-интерфейсом и покрыт сквозными интеграционными тестами.

---

##  Реализованные задачи повышенной сложности (Задания со звёздочкой)

*   **Аутентификация и безопасность (JWT):** Реализована генерация защищенных токенов при авторизации (сверка пароля с переменной окружения `TODO_PASSWORD`). Добавлена кастомная Middleware-функция для валидации токенов и надежной защиты эндпоинтов API от неавторизованных запросов.
*   **Контейнеризация (Docker Multi-stage build):** Написан оптимизированный `Dockerfile`, использующий многоэтапную сборку. В итоговый минималистичный образ копируется только скомпилированный бинарный файл, что гарантирует высокую безопасность и минимальный вес контейнера.

##  Архитектурные слои и возможности бэкенда

### 1. Веб-сервер и Статика (`net/http`)
*   Обеспечена бесперебойная раздача ресурсов фронтенда (`HTML`, `CSS`, `JS`, `favicon`) из папки `./web`.
*   Поддерживается динамическое назначение порта через переменную окружения `TODO_PORT` (дефолтный порт: `7540`).

### 2. Слой данных (SQLite)
*   Используется CGO-free драйвер `modernc.org/sqlite` для автономной работы приложения на любых платформах.
*   **Автомиграция:** При первом старте сервер автоматически генерирует файл базы данных `scheduler.db`, накатывает структуру таблиц и создает индекс `idx_date` по полю `date` для ускорения выборок и сортировки по дедлайнам.

### 3. Движок планирования дат (`NextDate`)
Реализован алгоритм вычисления следующей даты для периодических задач на основе поля `repeat`:
*   `d <число>` — повторение через N дней (например, `d 5`).
*   `y` — ежегодный повтор (с корректным учетом високосных лет).
*   `w <дни_недели>` — повторение в выбранные дни недели (1–7).
*   `m <дни_месяца> [месяцы]` — повтор в определенные числа месяца (включая `-1` и `-2` для обозначения последних дней).

### 4. REST API Спецификация
*   `POST /api/task` — Добавление задачи (авторасчет даты, если она в прошлом).
*   `GET /api/tasks` — Получение списка задач с поддержкой текстового и дата-поиска `?search=`.
*   `GET /api/task`, `PUT /api/task`, `DELETE /api/task` — CRUD-операции с конкретной задачей по `id`.
*   `POST /api/task/done` — Отметка о выполнении. Одиночные задачи удаляются, повторяющиеся — переносятся на дату `NextDate`.

##  Структура таблицы `scheduler`

| Поле таблицы | Тип данных в SQL | Описание |
| :--- | :--- | :--- |
| `id` | `INTEGER PRIMARY KEY AUTOINCREMENT` | Уникальный числовой ID записи |
| `date` | `CHAR(8) NOT NULL DEFAULT ""` | Дата выполнения в формате `YYYYMMDD` |
| `title` | `VARCHAR(256) NOT NULL` | Заголовок задачи (обязательное поле) |
| `comment` | `TEXT` | Подробное описание/комментарий |
| `repeat` | `VARCHAR(128) NOT NULL DEFAULT ""` | Строковое правило повторения задачи |

##  Инструкция по сборке и запуску через Docker

Приложение полностью готово к развертыванию в изолированном контейнере с сохранением (монтированием) базы данных на хост-машину.

### 1. Сборка Docker-образа
Находясь в корневой директории проекта, соберите образ:
```bash
docker build -t planner-app .
```

### 2. Запуск контейнера с монтированием базы данных

**Для Git Bash / Linux / macOS:**
```bash
docker run -d -p 7540:7540 -e TODO_PASSWORD="12345" -v "\$(pwd)/scheduler.db:/app/scheduler.db" --name planner-container planner-app
```

**Для Windows Command Prompt (cmd):**
```bash
docker run -d -p 7540:7540 -e TODO_PASSWORD="12345" -v "%cd%/scheduler.db:/app/scheduler.db" --name planner-container planner-app
```
